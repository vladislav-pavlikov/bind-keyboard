# Changelog

## 1.0.0

- New scopes API: tag a binding with `{ scope: "modal" }` in `.add()`'s options, then `enableScope()`/`disableScope()`/`setActiveScopes()` to control which scopes are active. A scoped binding only fires while its scope is active; unscoped bindings are unaffected and always fire. The same key combination can carry a separate binding per scope plus one more with no scope — whichever registered scope is currently active takes priority over the unscoped one. `getKeybind()`/`.remove()` both accept an optional `scope` argument to target a specific scoped binding; `getAllBindings()` now includes every scope.
- New key sequences: `.add("g,o", callback)` fires once every step is pressed in order, within `sequenceTimeout` ms of each other (new constructor option, default 1000). A comma right after a `+` is a literal comma key rather than a separator, so `"ctrl+,"` (a real Ctrl+Comma binding) and `"ctrl+,,g"` (a two-step sequence) are never ambiguous. Sequences support everything a plain binding does — `scope`, `allowInInputElements`, `description`, `override: false` — and coexist independently with plain bindings and with each other; two registered sequences that would complete ambiguously on the same press (one is a prefix of the other, both still matching) fire neither, with a `debug`-only warning naming both instead of guessing. OS auto-repeats of a held key are ignored for sequence matching, so simply holding a key doesn't complete a same-key sequence like `"g,g"` on its own.
- New `useKeybind` React hook, at the separate `bind-keyboard/react` entry point (`react` is a peer dependency, and only ever imported there — the core `bind-keyboard` import is completely unaffected either way). Creates its own `BindKeyboard` instance inside a `useEffect` and destroys it on cleanup; inherently SSR-safe since that effect (and so the instance) never runs on the server at all. Accepts everything `.add()`'s options do, plus `preventRepeat`/`type` (mirroring `.add()`'s own positional arguments), `enabled`, and the constructor options that matter per binding (`target`, `keyMode`, `checkInputElements`, `debug`).

- **`checkInputElements` now defaults to `true`** (was `false`) — bindings are skipped while an input/textarea/select/contenteditable is focused unless you opt out with `checkInputElements: false`, or opt a specific binding back in with `allowInInputElements: true`. The README and demo already described "input-safe by default" as a feature; the actual default didn't match that until now. Pass `checkInputElements: false` to restore the old (pre-1.0.0) behavior.
- Export the `Types` namespace (`import type { Types } from "bind-keyboard"`) so consumers can name `AddBindingOptions`, `KeybindCallback`, `ConstructorProps`, `KeybindInitializer`, `EventType`, `DebugLevel`, `KeyMode`, `KeyCombination`, `KeyCombinationConstruct` directly.
- Export `KeybindError` at the top level (`import { KeybindError } from "bind-keyboard"`), in addition to the existing `Classes.KeybindError`.
- `add()` now warns (under `debug`) when a registered combination commonly collides with a browser/OS shortcut (e.g. `ctrl+p` for Print) — informational only, never blocks registration.
- Removed the unimplemented chord/sequence `TODO`s from the source; noted as a known limitation in the README instead.
- Fixed the grammar of the "no key or modifier provided" error message.
- Fixed a lone modifier press (e.g. tapping Ctrl by itself) producing a combination like `"ctrl + control"`/`"ctrl + controlleft"` instead of plain `"ctrl"` — a binding registered as `"ctrl"` never matched a real standalone press of that key. Affected every modifier under `keyMode: "code"`, and `ctrl` specifically under `keyMode: "key"`.
- Fixed sequence parsing throwing a `SyntaxError` at module load — crashing the whole package for every consumer, not just the sequence feature — on Safari/iOS below 16.4 (March 2023). The comma-vs-literal-comma disambiguation relied on a negative-lookbehind regex (`/(?<!\+),/u`), a syntax older Safari/JavaScriptCore can't even parse; found by checking a real prior incident in tinykeys (jamiebuilds/tinykeys#85), which had shipped and then reverted the exact same construct. Rewritten as a manual character scan with identical behavior and no lookbehind.
- Fixed `checkInputElements`/`allowInInputElements` never detecting focus inside an **open** shadow root — `document.activeElement` only ever reports the shadow host itself, not the actually-focused input/textarea/etc. inside it, so a binding could fire while the user was typing in a web component's shadow DOM. Found via mousetrap's test suite, which has a dedicated case for the same scenario. A closed shadow root is intentionally still opaque (by spec, not a bug) and stops at its host, same as before.
- Fixed the literal `"+"` key never being bindable — `"ctrl++"` silently parsed as bare `"ctrl"` (dropping the key entirely), so a real Ctrl+Plus press never matched. Found via a hotkeys-js issue and mousetrap's own tests for exactly this. `"+"`, `"alt++"`, `"alt+shift++"` now all resolve correctly.
- The demo page's on-screen keyboard now matches the viewer's platform (Mac vs Windows/Linux) — correct `⌘`/`⌥` symbols, bottom-row key order, and `Delete`/`Return` labels on Mac — with auto-detection and a manual toggle.
- New `"cmdOrCtrl"` modifier alias in string key combinations (e.g. `"cmdOrCtrl+a"`), resolving to `metaKey` on Mac and `ctrlKey` everywhere else — matches each platform's own native shortcut modifier instead of always requiring the physical Ctrl key.
- Fixed holding a key and then also pressing a modifier (e.g. holding `d`, then also pressing `shift` for `"shift+d"`) unreliably matching, or not matching at all. Matching now tracks the currently-held non-modifier key itself, so a modifier's own keydown/keyup resolves the combination immediately and deterministically, instead of depending on the underlying key's next OS auto-repeat (which isn't guaranteed to update its own modifier flags, and was additionally getting swallowed by `preventRepeat` — that now only suppresses a genuine repeat of the same combination that last fired, not any repeat of the underlying physical key).
- `"keyup"` bindings now ignore `ctrlKey`/`shiftKey`/`altKey`/`metaKey` (and the `"cmdOrCtrl"` alias) entirely — `add("d", cb, true, "keyup")` fires on releasing "d" regardless of whatever other modifiers happen to still be held at that instant. Previously an exact modifier match was required for `"keyup"` too, so releasing a held key while a modifier was _also_ still down (e.g. dashing with `shift+d` while still holding `d` to move) could silently never fire that key's release binding, leaving whatever state it was meant to reset (e.g. "is this key held") stuck. `"keydown"`/`"keypress"` are unaffected — modifiers still fully matter there.
- The demo page's "Try it in your code" section now includes copy-pasteable examples for React, Vue, and Svelte (each in TS or JS), in addition to the existing Vanilla sample.
- Dropped the `lodash` dependency (`compact`/`uniq`/`isBoolean`/`isString`/`last`, used for a handful of one-line operations) in favor of plain JS equivalents — even importing each function "directly" still pulled in lodash's shared internal module graph, dominating the built bundle. Gzipped size drops from ~6KB/~5.5KB (ESM/UMD) to ~3.2KB/~3KB, with no behavior change.

## 0.1.0

Breaking changes from `0.0.11`:

- `add()`'s return type changed from `Map<string, KeybindEntry> | undefined` to `KeybindEntry[]`.
- `KeybindEntry`'s constructor changed from positional arguments to a single options object.
- `checkInputElements` now also suppresses bindings while a `<select>` or any `contenteditable` element is focused, not just `<input>`/`<textarea>`.

New features:

- `keyMode: "code"` — layout-agnostic matching via `event.code`.
- `add()` accepts an array of key combinations, and a 5th `options` argument: `allowInInputElements`, `override`, `description`.
- `destroy()` — stops listening and clears every binding in one call.
- The constructor no longer throws when the target has no `addEventListener` (e.g. during server-side rendering) — it warns and skips autostart instead.
- Fixed a bug where `add()` with an array of combinations could partially register bindings before throwing on a conflicting one under `{ override: false }`.
- Fixed `keyMode: "code"` not matching punctuation combinations added as a string (e.g. `add("ctrl+,")`).
